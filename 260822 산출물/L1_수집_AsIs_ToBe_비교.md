# L1 수집 단계 — As-Is → To-Be 비교 (개발자·기획 공유용)

> 대상: **1단계 수집**(데일리 파이프라인)만. 지식 계층·학습 루프·관점 정합은 별도.
> 목적: 현행 대시보드/파이프라인 대비 **무엇이 바뀌는지**와 **결정 필요사항**을 한 장에.
> 근거: `docs/데일리_파이프라인.md`·`docs/수집규칙.md`(현행) · 「L1 수집단계 구체화 가이드 v0.2」 · 소스 마스터 엑셀

---

## 한눈에 요약

- **바뀌는 핵심 3가지:** ① 수집 소스를 "키워드"에서 "**소스 마스터(5축·67소스)**"로 명시화 · ② 공개 **API/RSS·빅카인즈**로 자동 수집 안정화 · ③ 정기 발간물·전시회를 **캘린더**로 확보(현재 BSI·ESI만 → 전체 캘린더).
- **안 바뀌는 것:** 10대 분류·스코어링·4관점·대시보드·리포트 로직은 그대로(필드만 추가).

## 비교표

| # | 항목 | As-Is (현행 구현) | To-Be (구체화) | 결정 필요 |
|---|---|---|---|---|
| 1 | 수집 방식 | 키워드 7그룹 **일반 웹검색만** | 웹검색 + **빅카인즈 API** 보강(정형·재현) | 빅카인즈 가입·**API 키 발급 주체** |
| 2 | 소스 정의 | 키워드 목록만(어느 사이트인지 불명시) | **`sources.json` 소스 마스터**(축·방식·주기·URL·분류) | — (엑셀 → JSON 변환은 실무) |
| 3 | 소스 범위 | 뉴스 위주. 정기소스 **필수=BSI·ESI 2건**뿐 | 5 기본축 67소스 + 발간물/전시회/뉴스레터 | **1차 구현 범위**(가이드 ★ 5건 동의?) |
| 4 | 자동화 수단 | 없음(웹검색 의존) | 공개 **API/RSS 1순위 연결**(KOSIS·법령센터·정책브리핑·보안뉴스·네이버데이터랩) | API 키 발급 |
| 5 | 필수 수집 캘린더 | BSI·ESI 2건만 | 정기 발간물·전시회 **월별 캘린더** | **스코어링 면제(10점 고정) 대상** 확정 |
| 6 | 분류 vs 소스축 | 10대 분류(주제)만 | 10대 분류 + **5 기본축(`axis`) 병기** | 개발자 **스키마 반영** |
| 7 | 수집 스키마 | dt/title/summary/source/url/category/track | +`axis`/`source_id`/`collect_path`/`collect_method`/`is_required` (하위호환) | 개발자 합의 |
| 8 | 사내 신문스크랩 | (사실상) 웹검색으로 대체 | **사내 자료 유지** + 빅카인즈 보강 (수집 방식은 보류) | **사내 접근정책**(공용 수신함/폴더) |
| 9 | 트렌드 뉴스레터 | 미수집 | 네이버데이터랩(API)+블로그 크롤+뉴스레터 수신 | **공용 수신함** 운영 주체 |
| 10 | 실행 주체·경로 | 개발자 예약작업 = **경로 A(이벤트)만** | 경로 A 유지 + **경로 B(캘린더)** 추가 | 경로 B **실행 주체**(예약작업 vs 담당자 반자동) |

## 결정 필요 사항 — 요약 (담당별)

**개발자에게**
- 수집 스키마 신규 필드 5개(`axis` 등) 반영 · 빅카인즈/공개 API 연동 · 경로 B(캘린더) 스케줄러

**기획/운영에서 확정**
- 1차 구현 범위(정기 발간물 ★ 5건) · 스코어링 면제 대상 · 경로 B 실행 주체

**사내 정책 대기**
- 신문스크랩 사내 수집 방식 · 트렌드 뉴스레터 공용 수신함 · API 키 발급 주체
