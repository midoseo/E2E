## 0. 역할·목표 (Claude에게)

당신은 이 저장소(마켓센싱 대시보드)의 코딩 에이전트입니다. 목표는 **지식 계층(암묵지 KB)의 검증용 최소 구현**을 추가하고, **실제 기사 5~10건에 대해 "KB 근거 주입 전 / 후" 관점 해석을 나란히 비교한 샘플 테스트 결과물**을 산출하는 것입니다.

이 작업의 목적은 완성이 아니라 **검증**입니다: "베테랑의 판단 근거(KB)를 주입하면 관점 해석이 실제로 달라지고 좋아지는가"를 눈으로 확인할 수 있게 만드는 것.

## 1. 하드 제약 (반드시 지킬 것)

- **Additive only.** 기존 파이프라인(수집 · 스코어링 · 대시보드 · 리포트) 로직을 바꾸지 마세요. 새 모듈·새 산출 파일만 추가합니다.
- **관점은 3개**: `사업기획`, `상품기획`, `마케팅`. (기존 4관점의 `영업`은 `마케팅`에 병합. 관점 라벨은 이 3개만 사용.)
- 출력 언어는 **한국어**.
- LLM 호출은 이 저장소가 이미 쓰는 방식/키를 재사용하세요. 없으면 호출부를 함수 하나로 추상화하고 `# TODO: 실제 LLM 연결` 주석과 함께 모의(mock) 응답으로도 파이프라인이 끝까지 도는 형태로 만드세요.
- KB·결과는 **파일**로 저장(서버/DB 불필요).

## 2. 먼저 저장소를 파악하세요

작업 전에 아래를 읽고 실제 함수/파일명을 파악한 뒤 그에 맞춰 붙이세요(아래는 예상 구조이며, 실제와 다르면 실제를 따르세요):

- `build_dashboard.py` — 스코어링 통과 기사, 관점 분석, 채택/기각(localStorage `ms_dec`) 처리부
- `scripts/make_report.py` — 월간 리포트 생성
- `docs/데일리_파이프라인.md`, `docs/수집규칙.md` — 파이프라인 규칙
- 관점 분석을 수행하는 현재 코드(프롬프트 포함) — **여기에 KB 주입 슬롯을 얹습니다**

## 3. 입력 데이터 — 시드 KB

첨부 `kb_seed.json`을 로드합니다. 스키마:

```json
{
  "id": "KB-260904-001",
  "trigger": "판단을 촉발한 관찰(사실)",
  "axis_tag": ["사업기획"],            // 사업기획 | 상품기획 | 마케팅 (복수 가능)
  "judgment": "그 신호를 무엇이라 읽었나 (결론 한 문장)",
  "rationale": "★왜 그렇게 읽었나 (경험 규칙·정황 — 핵심)",
  "counter": "고려했으나 버린 반대 해석",
  "boundary": "이 근거가 통하는/통하지 않는 조건",
  "result": "실제 전개·검증(미검증이면 보류)",
  "confidence": "높음|중간|낮음",
  "decision": "채택|기각|게재|미게재|보류",
  "status": "유효|재검토|폐기",
  "source": "작성자",
  "origin": "field"
}
```

시드는 현업 9건(현재 사업기획 6 · 마케팅 2 · 상품기획 1). 일부는 **'게재/미게재 판단 규칙'**(예: "공공 조달은 노이즈", "공급 뉴스 개수 ≠ 시장 크기")이라는 점에 유의 — 이런 근거는 특히 잘 살려 주세요.

## 4. 구현 항목

### 4-1. KB 로더
`kb_seed.json`을 읽어 메모리로 로드하는 함수. (`kb/kb_seed.json` 경로 권장)

### 4-2. KB 검색 (retrieval) — ★검증으로 갱신됨
`related_kb(article, axis) -> List[KBEntry]`:
- **1차 필터**: `axis_tag`에 해당 관점 포함
- **2차 개념 게이트(핵심)**: KB의 `match_keywords`(각 항목에 큐레이션됨) 중 하나라도 기사 텍스트에 나타나야 후보로 인정. **하나도 없으면 제외** — 어휘만 겹치는(예: 'AI·CCTV·영상분석') KB를 배제하기 위함.
- **3차 정렬**: 게이트를 통과한 후보를 `score = 10×개념매칭수 + 0.3×IDF가중 어휘겹침`으로 정렬. (IDF: 흔한 단어일수록 가중치↓)
- 상위 `N=2~3`건 반환. 게이트 통과가 없으면 **빈 리스트**(KB 주입 안 함).

> **왜 이렇게? (실측 근거)** 단순 키워드 겹침(v1)은 '무인매장 33% 급증' 기사에 개념적으로 맞는 KB(공급≠수요)를 놓치고, 어휘만 겹치는 KB(공공 CCTV 노이즈)를 골랐다. 개념 게이트(v2)로 바꾸자 올바른 KB가 선택됐고, 그 결과 관점 해석의 품질이 실제로 향상됨(검증 메모 참조). **텍스트 유사도 ≠ 규칙 적합도.**
> 참고 구현: 첨부 `retriever.py`(개념 게이트 + IDF). 추후 여력이 되면 `match_keywords`/규칙 문장 단위 **임베딩**으로 고도화 가능(원문 전체 임베딩은 같은 함정에 빠질 수 있으니 '규칙' 단위로).

### 4-3. 관점 에이전트
`analyze(article, axis, kb_list) -> {judgment, rationale, boundary}`:
- `kb_list`가 비어 있으면 = **A(현행: KB 없음)**, 있으면 = **B(KB 주입)**
- §6 프롬프트 템플릿 사용
- 출력은 반드시 `judgment` / `rationale` / `boundary` 3필드(JSON)

### 4-4. A/B 실행 드라이버
`run_sample_test(articles) ->` 각 (기사 × 관점 3개)에 대해 A와 B를 모두 실행하고 결과를 모읍니다.

## 5. 데이터 계약 — 결과물 스키마

`out/sample_test.json`:
```json
{
  "generated_at": "2026-09-..",
  "results": [
    {
      "article": {"id": "...", "title": "...", "url": "..."},
      "axis": "상품기획",
      "injected_kb_ids": ["KB-260904-003"],
      "A_no_kb":  {"judgment": "...", "rationale": "...", "boundary": "..."},
      "B_with_kb":{"judgment": "...", "rationale": "...", "boundary": "..."}
    }
  ]
}
```

## 6. 프롬프트 템플릿 (그대로 사용)

**A) KB 없음 (현행 재현):**
```
당신은 에스원의 [관점] 담당자입니다.
아래 기사를 [관점] 관점에서 해석하세요.
결론(judgment) / 근거(rationale) / 경계조건(boundary)을 각각 한국어로 제시하세요.

[기사]
제목: {title}
본문: {body}
```

**B) KB 주입:**
```
당신은 에스원의 [관점] 담당자입니다.
과거 우리 조직은 유사한 신호를 이렇게 읽어왔습니다(판단 근거):

{관련 KB를 아래 형식으로 나열}
- 신호: {trigger}
  판단: {judgment}
  근거: {rationale}
  경계조건: {boundary}

위의 '판단 방식과 근거'를 참고해, 아래 기사를 [관점] 관점에서 같은 결로 해석하세요.
특히 표면적 사건이 아니라 '무엇을 근거로, 어디까지(경계조건)' 읽어야 하는지에 주목하세요.
결론(judgment) / 근거(rationale) / 경계조건(boundary)을 각각 한국어로 제시하세요.

[기사]
제목: {title}
본문: {body}
```

## 7. 산출물 (완료 정의)

1. `out/sample_test.json` — §5 스키마
2. `out/sample_test.html` — **사람이 볼 비교표.** 행 = 기사×관점, 열 = [기사 | 관점 | 주입 KB id | A) KB 없이 | B) KB 주입]. A/B가 다른 부분이 한눈에 보이게(간단한 강조면 충분).
3. `IMPLEMENTATION_NOTES.md` — 짧게: 무엇을 어디에 붙였는지, LLM 연결 방식, retrieval 방식, **KB가 부족해 보이는 지점(어떤 관점·주제의 근거가 더 필요한지)**.

## 8. 샘플 기사 선정

- 최근 수집·스코어링 통과분에서 5~10건. 가능하면 세 관점에 고루 걸리는 것.
- 저장소에 최근 통과 기사 데이터가 있으면 그걸 쓰고, 없으면 `docs`나 캐시에서 찾거나, 없으면 대표적 보안·안전 관련 샘플 기사 5건을 `out/sample_articles.json`에 만들어 사용(그 사실을 NOTES에 명시).

## 9. 이번 범위 밖 (하지 말 것)

- 대시보드 검토기록 UI 확장(rationale·boundary 입력칸)
- localStorage → 서버/DB 전환
- KB 자동 축적(채택 결과 write-back)

이 세 가지는 샘플 테스트로 효과가 확인된 뒤 다음 단계에서 진행합니다.

---

### 실행 순서 요약
저장소 파악(§2) → KB 로더(4-1) → retrieval(4-2) → 관점 에이전트(4-3) → A/B 드라이버(4-4) → 샘플 기사(§8) → 산출물 3종(§7). 완료 후 `out/sample_test.html`을 열어 A/B 차이를 육안 확인.
